# YouTube → mp3 бот

Телеграм-бот с одной задачей: присылаешь ссылку на YouTube — получаешь mp3
с названием, исполнителем и обложкой.

## Установка

Нужен Python 3.11+ и ffmpeg.

```
winget install Gyan.FFmpeg
pip install -r requirements.txt
```

После установки ffmpeg перезапусти терминал, иначе PATH не подхватится.

## Настройка

Создай файл `.env` рядом с `main.py`:

```
BOT_TOKEN=токен_от_BotFather
```

Токен берётся у [@BotFather](https://t.me/BotFather): команда `/newbot`.

## Запуск

```
python main.py
```

## Проверка без Telegram

Скачивание можно проверить отдельно от бота, токен не нужен:

```
python -m services.downloader "https://www.youtube.com/watch?v=..."
```

## Что учтено

- **Лимит Telegram 50 МБ.** Ролики длиннее часа отклоняются до загрузки.
  Если готовый файл всё же перевалил за 45 МБ, он автоматически
  перекодируется в 128 kbps, и только если и это не помогло — отказ.
- **Бот не зависает.** yt-dlp синхронный, поэтому уходит в отдельный поток:
  во время скачивания бот продолжает отвечать другим.
- **Одновременных загрузок не больше двух**, и один пользователь не может
  запустить вторую, пока не закончилась первая.
- **Временные файлы удаляются всегда** — каждая загрузка живёт в своей папке
  внутри `downloads/`, которая сносится в `finally` даже при ошибке.
- **На серверах YouTube не блокирует** — в том же контейнере рядом с ботом
  поднимается локальный генератор PO-токенов (bgutil-ytdlp-pot-provider),
  который снимает проверку «Sign in to confirm you're not a bot» с серверных IP.
- **Ошибки разделены.** Понятные причины (приватное видео, эфир, слишком
  длинное) показываются пользователю текстом, всё остальное уходит в лог,
  а человек видит короткое сообщение.

## Структура

```
main.py                 запуск, окружение, подъём PO-сервера
config.py               настройки и лимиты
handlers/audio.py       хендлеры Telegram
services/downloader.py  yt-dlp и ffmpeg, без зависимости от aiogram
services/pot_provider.py  локальный генератор PO-токенов (Node)
```

`downloader.py` и `pot_provider.py` не импортируют aiogram сознательно:
логику скачивания и запуск токен-сервера можно тестировать и переиспользовать
отдельно от бота.

## Как это обходит блокировку YouTube

`yt-dlp` подключает плагин `bgutil-ytdlp-pot-provider` (прописан в
`requirements.txt`). Плагин умеет запрашивать proof-of-origin токены у
HTTP-сервера. Этот сервер (Node) поднимается в том же Docker-контейнере на
`127.0.0.1:4416` и генерирует токен, который YouTube принимает как «это не бот»
— даже с серверного IP дата-центра.

Запуском занимается `main.py → services/pot_provider.py`: стартует `node
build/main.js`, ждёт `GET /ping` и только потом начинает polling. При остановке
бота сервер гасится вместе с ним. Если сервера нет (например, локально, где
скачивание и так работает) — бот просто продолжает без PO-токенов.

## Известные ограничения

- YouTube периодически меняет анти-бот защиту. PO-токен решает проблему
  «Sign in to confirm you're not a bot», но за идеальной надёжностью нужно
  следить за обновлениями `yt-dlp` и `bgutil-ytdlp-pot-provider`.
- 50 МБ — жёсткий лимит Telegram Bot API. Обходится только своим
  Bot API сервером.
- Скачивание контента с YouTube противоречит их правилам использования.
  Инструмент для личного использования.

## Деплой на Render (бесплатно)

Бот держится в бесплатном плане Render: один web-сервис, Docker, 512 МБ RAM.
Polling работает как локально, дополнительно поднимается health-эндпоинт —
платформе он нужен, чтобы считать сервис живым.

### 1. Репозиторий

Залей проект на GitHub. Файл `.env` в репозиторий не попадает — он в `.gitignore`.

### 2. Сервис

На [render.com](https://render.com) → **New → Web Service** → подключи репозиторий.
Runtime определится как Docker автоматически. План — **Free**, регион — Frankfurt.

### 3. Переменные

В разделе **Environment**:

- `BOT_TOKEN` — токен от BotFather

Порт `PORT` Render задаёт сам, руками его добавлять не надо.
PO-токены включены по умолчанию: сервер поднимается сам в контейнере,
ничего настраивать не требуется.

### 4. (Опционально) Cookies YouTube

Иногда PO-токена недостаточно, и YouTube всё равно просит подтверждение.
Тогда помогает cookies залогиненного аккаунта как дополнительный слой.

1. Заведи **отдельный** гугл-аккаунт, не основной: за автоматические
   загрузки аккаунт могут заблокировать, и терять личный не стоит.
2. Зайди под ним на youtube.com в браузере.
3. Экспортируй cookies расширением в формате Netscape (`cookies.txt`).
4. В Render: **Environment → Secret Files → Add Secret File**,
   имя `cookies.txt`, содержимое — файл целиком.
5. Добавь переменную `COOKIES_FILE=/etc/secrets/cookies.txt`.

Без этого бот тоже запустится, но часть ссылок с заблокированных IP
будет отваливаться.

### 5. Чтобы сервис не засыпал

Бесплатный web-сервис Render засыпает после 15 минут без запросов, и бот
перестаёт получать сообщения. Лечится внешним пингом:

На [cron-job.org](https://cron-job.org) (бесплатно, без карты) создай задание:
`https://<твой-сервис>.onrender.com/health`, интервал 10 минут.

Бесплатный план даёт 750 часов в месяц — на один сервис в режиме 24/7
этого хватает ровно (744 часа в месяце из 31 дня). Второй бесплатный
сервис в тот же месяц уже не влезет.

### Что делать, если YouTube всё равно блокирует

PO-токен разворачивается и собирается автоматически в Docker. Если блокировка
всё же возвращается, порядок действий по возрастанию усилий:

1. Обнови `yt-dlp` и плагин `bgutil-ytdlp-pot-provider` — экстракторы и
   механика BotGuard правятся почти каждую неделю.
2. Обнови сборку образа (Manual Deploy) — иногда нужно просто перезапустить
   сервер PO-токенов, чтобы обновились его внутренние таблицы.
3. Добавь свежие cookies залогиненного аккаунта (см. пункт 4) как второй слой.
4. Если и это не помогает — вопрос упирается в репутацию IP, и бесплатно
   он не решается. Варианты платные: резидентный прокси (от пары долларов
   в месяц) либо мини-ПК дома, где IP домашний и вопросов не возникает.
